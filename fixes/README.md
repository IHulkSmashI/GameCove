# Device fixes

One folder per fix, each with `fix.sh` (`install | remove | status`, some `set <value>`) and
`test.sh` (runs against a fake root, never the real system). They run as root through
`packaging/libexec/gamecove-fix` (admin password) or, for the small file fixes and the everyday
settings, `gamecove-fix-set` (no password). What each fix is for, who gets it automatically and the
research behind it: `app/data/fixes.json` and [docs/DEVICE-FIXES.md](../docs/DEVICE-FIXES.md).

## File fixes (`lib/gcfix.sh`)

The udev and session-file fixes share `lib/gcfix.sh`. A fix names its devices (devices.json ids,
looked up from DMI through `lib/devices.txt`, generated by `tools/fixes/gen_handhelds.py`), the
files it writes, and four small functions: `file_text`, `hw_present`, `os_fixed`, `apply_now`.

- `install` (= `set on`): only on the listed handhelds (else exit 2); "not needed" (exit 0, nothing
  written) when the system already does it or the part isn't there; writes the file with a
  `# GameCove fix <name>` first line (never over someone else's file), reloads udev, applies the
  value at once and saves the original.
- `remove` (= `set off`): deletes only its own file, writes the saved values back.
- `status`: `applies=`, `installed=`, `os_fixed=`, `hw=`, then `state=` one of `on`, `off`,
  `os-fixed` (the OS ships the same rule, or the value is already right without us), `not-needed`,
  `partial`, `n/a`.
- Every rule also matches the DMI ids itself, so one drive booting several handhelds never applies
  a fix to the wrong one.
- One run at a time (`/run/gamecove-<name>.lock`); changes logged to
  `/var/lib/gamecove/fixes/<name>/changes.log` and gamecove-fix's log.

Tests: `fixes/<name>/test.sh` with `lib/tests/gcfix-testlib.sh` (`t_common` checks install,
idempotence, remove, set on/off, foreign files, os-fixed, other handhelds, no DMI).
